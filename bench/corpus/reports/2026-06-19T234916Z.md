## Root cause of 0/21 coverage (observed, supersedes the per-site block labels above)

The per-site "blocked — class=anti-bot/cloudflare/datadome" lines are the corpus's PRE-ASSIGNED
block_class tags, NOT the observed failure. Observed reality (verified by a manual resolve on
wikipedia/HN/stackoverflow): the shipped binary's `eval resolve` returns **HTTP 200 with a
populated `raw.exa_results` web-search shortlist but an EMPTY route `shortlist` (count=0)** for
every site. The harness scores `shortlist` (route-graph endpoints), so coverage = 0/21.

**Why:** this run graded the freshly-shipped **experiments PREVIEW CLI**
(`9.10.0-preview.0-experiments.3c5e602`) against the **PREVIEW backends** (staging AND
experiments) — both return empty route shortlists because preview backends carry **no
accumulated route index**. PROD (`api.unbrowse.ai`, which has the real index) is **unreachable
by the preview binary** (non-JSON response). So this is a backend-data-state + binary-pinning
finding, not an anti-bot defeat.

**Regression context:** prior corpus 2026-06-13 = **29/50 (58%)** covered (it hit an indexed
backend); this run = **0/21 (0%)** against empty preview backends. The drop is the backend, not
a resolve-contract crash — the contract works (200 + exa fallback) end to end.
