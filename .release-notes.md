## What's New

**Probe-first executor.** The strategy decision no longer comes from a cached `exec_strategy` label that gets stale. Every execute now starts with a cheap HEAD probe (with browser headers + cookies, ranged-GET fallback for HEAD-rejecting servers) and dispatches based on the actual response signal — content-type, body size, status. Self-fetchable URLs never call `triggerAndIntercept`, so the reddit `/comments/{id}/{slug}/.json` class of `trigger_timeout` after 15s is gone — that case now returns the actual server status (200/403/404) within 1s.

**Recipe replay.** When an endpoint was admitted from a real captured request, we now persist the proven recipe — exact method, headers, body, and a response signal (status, content_type, byte length range, top-level JSON keys). Execute replays that recipe first; if it matches, you're done in <500ms with no probing. If the recipe drifts (status changed, body shape changed), we fall through to the probe ladder.

**`decision_trace` on every execute response.** The response envelope now carries a `decision_trace: [{step, ...}]` array showing every probe, recipe-replay attempt, dispatch, and fallback the executor took, with millisecond timings. Debugging an execute no longer needs stderr capture or a recompile — the trace is in the JSON.

## Fixes

- Reddit `/comments/{id}/{slug}/.json` returns server status in <1s (was: `trigger_timeout` after 15s)
- Every other class of "executor picked the wrong strategy and waited forever" is now a 2xx/4xx with a `decision_trace` showing exactly what happened
