## Fixes

- **D8b — graphql variables actually reach the wire now.** v6.1.3 borrowed the sibling endpoint's body but the captured body contained inline placeholder strings (e.g. `{variables_seentweetids_0}`) that `interpolateObj` doesn't rewrite. The cleaned `variables` / `features` built by `buildGraphqlRequestParams` were going into `mergedParams` but never read for body-based POSTs. Now they are written directly into `body.variables` / `body.features`, eliminating placeholder leak through to x.com (and similar GraphQL hosts).
