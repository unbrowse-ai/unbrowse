# Unbrowse v6.16 — Architecture Overview

**Released:** v6.16.0-preview.0 (2026-05-14)
**Tag:** [v6.16.0-preview.0](https://github.com/unbrowse-ai/unbrowse-dev/releases/tag/v6.16.0-preview.0)
**Audience:** integrators, agent builders, anyone calling Unbrowse from an SDK or HTTP client

This is the public-facing architecture explanation. For migration instructions read [`x402-flex-migration.md`](./x402-flex-migration.md). For the flywheel narrative read [`x402-flywheel.md`](./x402-flywheel.md). For wallet + escrow + session-key setup read [`wallets.md`](./wallets.md).

---

## 1. What v6.16 changed

Unbrowse's settlement layer pivoted from older payment shims onto **Faremeter Flex** (`@faremeter/flex`). The new scheme carries multi-recipient splits *natively* in every signed authorization — the platform's cut and contributor payouts ride a single off-chain Ed25519 signature and settle on-chain in batches via the canonical Solana x402 facilitator pattern.

Onboarding tightened: every agent must pair a wallet, fund a Flex escrow, and register a session key before getting an API key. Existing v6.15-era agents see a 402 with `X-Flex-Onboarding-Required: 1` on priced routes until they complete the same flow. Free routes (health, search-read) are unaffected.

Indexer rewards now flow through the same Flex splits as the payment itself — contributors are paid USDC atomically with every settle, no separate claim step. Reward weighting is attribution-driven (see §3).

## 2. The wire layer — `@faremeter/flex`

### 2.1 Payment-required envelope

When a priced route receives an unsigned request, the backend responds with a v2 x402 envelope:

```json
{
  "x402Version": 2,
  "error": "Payment Required",
  "resource": { "url": "...", "description": "Skill access: <skill_id>", "mimeType": "application/json" },
  "accepts": [{
    "scheme": "@faremeter/flex",
    "network": "solana-mainnet",
    "amount": "<max_uc>",
    "asset": "EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v",
    "payTo": "<agent_escrow_pda>",
    "maxTimeoutSeconds": 60,
    "extra": {
      "flexAuthorizationDraft": { "escrow", "mint", "maxAmount", "authorizationId", "expiresAtSlot", "splits" },
      "programId": "<FLEX_PROGRAM_ADDRESS>"
    }
  }]
}
```

The `accepts[].extra.flexAuthorizationDraft` is the unsigned authorization the client signs with their session key.

### 2.2 Signing path

The SDK catches `PaymentRequiredError` and calls `payAndRetryFlex(error, wallet, retry)`. The wallet's session key signs the authorization with `signPaymentAuthorization` from `@faremeter/flex-solana`; the resulting `FlexPaymentPayload` is base64-encoded into an `X-PAYMENT` header. The backend verifies via the platform's Flex facilitator.

### 2.3 Settle path

Facilitator runs `handleVerify(requirements, payload)` → hold reserved → route executes the skill → facilitator's `handleSettle` finalizes the actual amount used (≤ `maxAmount`). Background flush submits batched on-chain transactions. After the refund window closes, `finalize` distributes USDC per the signed `splits` array.

## 3. Indexer rewards

Unbrowse's marketplace pays indexers for the routes other agents reuse. Rewards are weighted by attribution — contributors whose routes consistently work get more than those whose routes don't.

Rewards land two ways per execution:

1. **On-chain Flex settlement** — USDC paid by the agent (or sponsor escrow) distributes to contributors at finalize time per the signed splits.
2. **Attribution fee ledger** — per-execute credit to the indexer's account ledger (off-chain, withdrawable). Visible via `GET /v1/stats/indexer/:indexer_id/ledger`.

Both update on the same execution; the indexer sees their earnings consolidated on the `/account` dashboard.

The exact weighting formula is not part of the public surface — verify against the live `/v1/stats/indexer/:indexer_id/ledger` and `/v1/stats/attribution/summary` endpoints rather than assuming a fixed model.
## 4. Onboarding gate — wallet + escrow + session key

### 4.1 Why three steps?

Flex requires the agent to:

1. **Pair a wallet** — a Solana address that owns the escrow PDA and signs on-chain ops.
2. **Fund a Flex escrow** — pre-deposit USDC into a program-derived account owned by the agent + facilitator pair.
3. **Register a session key** — an Ed25519 keypair stored locally that signs payment authorizations off-chain (so the agent never signs with the wallet's main key on every request).

Without all three, the agent can't sign valid authorizations.

### 4.2 Where the gate enforces

| Surface | Behavior |
|---|---|
| `unbrowse setup` CLI | Honest-skip wizard; prints SDK + web URLs for each missing step; ends with "Onboarding partial — priced calls will receive 402 until completed." |
| `POST /v1/agents/register` | Rejects requests missing any of the three fields. |
| Priced routes (`/skills/:id/execute`, `/v1/execute`, `/search`) | Returns 402 `X-Flex-Onboarding-Required: 1` for legacy agents missing fields. |
| Free routes (`/health`, `/search` read-only) | Skip the gate; legacy agents can still inspect their account. |
| `/account` UI | Three sequential CTAs: Pair wallet → Fund escrow → Register session key. |

### 4.3 `AgentProfile` schema additions

```ts
interface AgentProfile {
  wallet_address?: string;
  flex_escrow_address?: string;       // base58 PDA
  flex_session_key_address?: string;  // base58 Ed25519 pubkey
  flex_facilitator?: string;          // optional override for the default facilitator
}
```

All three new fields are optional in the type (backward-compat with legacy rows) but required at registration.

## 5. Sponsor mode

The platform sponsors the first calls per new agent so the marketplace flywheel kicks in before the agent has funded their own escrow. Sponsor logic includes per-agent and per-platform daily limits; once exhausted, agents fall through to paying from their own escrow.

In v6.16-preview.0 the sponsor rail runs alongside the previous payment path, behind a feature flag, so the v6.15 cold-start behavior remains the default through this preview cycle.

## 6. Public surfaces

### 6.1 `GET /v1/analytics/payments`

Returns an analytics envelope with `_partial: true` + `_instrumented_fields: [...]` flags so consumers can distinguish real-instrumented metrics from placeholders (where the underlying ledger is still being wired in subsequent previews).

Today's instrumented fields:

- `sponsor_settled_usd_24h` — total USDC settled by sponsor mode in the last 24 hours
- `sponsor_recouped_usd_24h` — platform's share recouped via Flex splits in the last 24 hours

The rest of the envelope (platform-cut totals, creator-payout totals, in-flight Flex state) will become real-instrumented in subsequent previews. `_partial: true` means "consumer, treat the unmarked fields as placeholders."

### 6.2 `GET /v1/stats/indexer/:indexer_id/ledger`

Returns per-indexer attribution ledger: `total_credited_uc`, `total_credited_usd`, `execution_count`, `first_attributed_at`, `last_attributed_at`, plus attribution-weight fields visible only to the indexer themselves. This is what an indexer sees as "my earnings on Unbrowse."

### 6.3 `GET /v1/stats/attribution/summary`

Global rollup of attribution across all indexers.

## 7. Environment variables (integrator-facing)

These are the v6.16 vars relevant to anyone running Unbrowse on their own infrastructure or pointing the SDK at a non-default facilitator:

| Var | Required? | Description |
|---|---|---|
| `FLEX_PLATFORM_RECIPIENT_USDC_ATA` | yes (prod) | USDC ATA owned by the platform — recipient of the platform cut in every authorization. |
| `FLEX_REFUND_TIMEOUT_SLOTS` | no | Refund window before pending settlements finalize. Range: 150 slots (~1 min) to 1,296,000 slots (~6 days). Default 150. |
| `FLEX_DEADMAN_TIMEOUT_SLOTS` | no | Client recovery timeout if facilitator becomes unresponsive. Range: 1,000 to 2,592,000 slots. Default 1000. |

Operator-only env vars (facilitator keys, sponsor wallet, etc.) are documented in the deployment runbook.

## 8. Migration for builders

### 8.1 Calling Unbrowse via SDK

```ts
import { Unbrowse, PaymentRequiredError } from "@unbrowse/sdk";
import { payAndRetryFlex } from "@unbrowse/sdk/flex";

const u = await Unbrowse.local();
try {
  const r = await u.execute(skill, input);
} catch (e) {
  if (e instanceof PaymentRequiredError) {
    const r = await payAndRetryFlex(e, wallet, (header) =>
      u.execute(skill, input, { headers: { "X-PAYMENT": header } }));
  }
}
```

`Unbrowse#executeMetered` exists in the SDK but throws a version-targeted error pending a subsequent preview that wires the metered route handler.

### 8.2 Calling Unbrowse via HTTP

The 402 envelope now has `scheme: "@faremeter/flex"` and `extra.flexAuthorizationDraft + programId`. Sign an Ed25519 authorization with your session key against the platform's `FLEX_PROGRAM_ADDRESS`, base64-encode a `FlexPaymentPayload`, pack into `X-PAYMENT`. Full step-by-step is in [`x402-flex-migration.md`](./x402-flex-migration.md).

### 8.3 Onboarding new agents

`POST /v1/agents/register` requires `{email, wallet_address, flex_escrow_address, flex_session_key_address}`. Missing any returns a 400 with the `missing[]` array so callers can show the user which step still needs completion. Walk users through `unbrowse setup` (CLI) or `/account/{wallet,escrow,session-key}` (web).
