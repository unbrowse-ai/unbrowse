# The engine rebuild

Written 13 November 2026, on `feat/engine-rebuild-2026-11-13`. It rebuilds the path from a walk to a call
(learn, route, call) around the design the last two days arrived at, as one new core beside the old one, and retires
the old one when the new one is measured to be at least as good.

It adds no design of its own where one is already chosen. The design is in `unbrowse-ai/unbrowse-graph`
(`decide.site-harness`, `decide.coverage-kpi`, `learn.record`, `learn.lab`, `learn.derivation`, `learn.rung`,
`learn.reference`, `learn.isolate`, `learn.proposer`, `learn.lifetime`, `learn.matrix`, on its
`proposal/site-harness-2026-11-12` branch) and in the canvas note `plan-a-harness-that-generates-harnesses.md`,
steps 10 and 11. This page says how the engine is rebuilt to be that design, in what order, and how each part is
proved. Read the nodes for the rules; they are not restated here.

## 1. Why rebuild, and not keep adding

Measured on the base (`c89ba7cd`, the tip of `feat/doors-sharing-2026-11-08` when this branch was cut):

| Fact | Number |
|---|---|
| `app/src/learn.rs` | 9,138 lines, with 2,034 more in `app/src/learn/` |
| `crates/learn/src` | about 31,000 lines; `client.rs` 3,642, `graph.rs` 2,933, `sandbox.rs` 2,714, `replay.rs` 2,228 |
| Commits on the line since 8 November | about 290, most of them one property found on one site |
| Ways a request value can be made (`graph::Class`) | 12 variants, plus `Held`, `Written`, `Piece`, `page_signed`, and `Wrap` on PR 550 |

The design changed under that code. On 8 November a route was one walk, classified field by field. By 13 November
it is two walks measured against each other, a proposer for what they leave open, the site as judge, and a ladder
of makers per value. Each of those arrived as a pass run after the one-walk classifier: `experiment.rs`, `trial.rs`,
`links.rs`, and PR 554's `measured`. The classifier still writes the first draft, so its ties are made and then
undone (Pinterest: eight steps cut to one; Marriott: a chain where one plain call answers).

The note's revised step 10 says why the form itself has to change: a fixed list of classes cannot say what a site
does when a value is picked from a list, changed on the way, or worked out from two sources, and every case outside
the list needs a new rule. `Class` is that list. The rebuild replaces it with expressions, makes learning by example
the first pass and not the fourth, and gives the caller one evaluator.

## 4. The shape

Three parts, each with one job and one test of its own.

```
walks (recordings)                       the body                        a call
┌───────────────┐   learn by example   ┌──────────────┐   fill holes   ┌──────────────┐
│ every sighting│ ───────────────────▶ │ steps, holes,│ ─────────────▶ │ requests over│
│ of each call  │   crates/learn/lab   │ ways, tests  │  crates/route  │ the transport│
└───────────────┘                      └──────────────┘                └──────────────┘
        ▲                                     ▲                               │
        └── the Site oracle: live, or         └── from_graph: every route     └── rung per hole,
            answered from the recording           the node holds today            lifetimes, no repair
```

| Part | Where | Depends on | Replaces |
|---|---|---|---|
| The body and its evaluator | `unbrowse-node/crates/route` (new crate `unbrowse-route`) | `serde`, `url`, hashes. No browser, no TLS, no model | `graph::Class` and the per-class branches of `replay.rs` |
| The learner by example | `unbrowse-node/crates/learn/src/lab/` | `Trace`, `Recording`, the readers, `Fetch` | `graph::build`'s classifier, `learn.rs`'s pick and keep, `links.rs`, `trial.rs` |
| The caller | `unbrowse-node/crates/learn/src/fill.rs` | the evaluator, `Fetch`, `Rung` | `replay::run`'s field loop, the heal paths of `client.rs` |

The body is a crate of its own so that it builds and tests in seconds on a loaded machine, and so that what a
shared route may hold is decided in one small place.

## 5. The body

A route body is data, never code (`R2.7`), and a graph (`R2.9`). The graph is and-or, as step 10 names it: a
**hole** is a place in a request; a **way** is one expression that fills it, needing all its sources; a hole may
have several ways and any one will do. The caller takes the cheapest way that is ready (`learn.rung`).

| Thing | Holds |
|---|---|
| Route | version, site, slots, steps, the answer, its tests, its plan |
| Slot | a name, a kind, the walked value as an example, the choices the page offers, optional or not, secret or not |
| Step | method, address and body as templates of holes, the statuses expected, read or write, a lifetime (`learn.lifetime`) |
| Hole | where it sits, and its ways in rung order |
| Way | a rung and an expression |
| Answer | which step, and which fields are the result, as expressions over the reply |
| Test | a sighting as shapes: these sources gave a value of this shape. No value of a session travels |
| Plan | the page, the goal, what was done on the page, which slot each asked value fills: enough to learn the route again |

Expressions are a closed list. Sources: a fixed text, a slot, a cookie by name, a stored value by key, a place in
an earlier step's reply, the clock, randomness of a shape, a fact about a file. Operations: join, slice, change
case, encode and decode (percent, plus, base64, hex, JSON), hash and keyed hash, pick the item of a list that fits,
format a number or a time. Functions: a pointer to a function of the site's own script (`learn.reference`), and a
generated program, which is the route's private data and is never shared. An operation the evaluator does not know
refuses the whole body.

Every way a value is made today is one of these, so every route the node holds keeps running:

| Today | In the body |
|---|---|
| `Constant` | a fixed text |
| `Input` | a slot |
| `Held` with `Written` (the word inside a longer value) | a join of fixed pieces around the slot, encoded as written |
| `Piece` | a slice of a slot |
| `Derived` | a place in an earlier reply |
| `Minted` | a cookie, or a stored value |
| `Fresh` | a join of fixed text and the clock or randomness |
| `Recipe` | a hash over a join |
| `Generated` | a generated program (rung 2) |
| `Script`, `Computed`, `page_signed` | a way at rung 3 for the step, then rungs 4 and 5 |
| `File` | a fact about a file |
| `Unconfirmed` | a fixed text, and the hole marked open |
| `Wrap` (PR 550) | an encoding around JSON that holds the slot |

`from_graph` makes the body from a `Graph`. It is the bridge for the whole rebuild: the caller can be replaced
before the learner is, and proved by sending the same bytes the old replay sends.

## 6. The learner

`compile(recording) -> body`, deterministic, so anyone can compile a recording again and check the result (`R2.11`).

1. **Sightings.** Every sighting of one operation, across all the walks of a learn and the learner's own asks, is
   lined up (same site, method, path shape and, at a shared address, the same operation). Each is labelled with
   what differed when it was made: the asked value, the time, the session, a control. The axis is recorded by
   whatever made the sighting and never assumed; two walks of one learn differ in the word and the time, not the
   session (the mistake step 2 made and reverted).
2. **Holes.** Each request is flattened into holes by the readers the engine already has. The reply is flattened
   the same way.
3. **Expressions by example.** For each hole, candidate expressions are enumerated over the sources and kept only
   if they rebuild the value on every sighting. The parts that do not move are sources too. A hole whose length
   says it is a hash is searched over the call's own values, the cookies' pieces, the clock and fixed keys. What
   survives is the hole's ways. A hole with none is open and says on which axes it was seen.
4. **The answer.** The call both walks make whose reply changes with the value and says it back; the page counts.
   The same comparison over the reply says which fields are the result.
5. **The proposer** (`learn.proposer`) is shown only what is still open, in the same form: an expression for a
   hole, a name for a slot, which call a person came for. A proposal is checked offline against every sighting
   before any site is asked. A node with no proposer keeps what enumeration found.
6. **Shrinking.** A read is tried with one part left out at a time: a header, a cookie, a step. A part stays out
   while the site still answers each word as itself. What is left is the least request the site accepts. A write
   is never tried (the note's rule for writes stands).
7. **The site's test.** A second value answers as itself, a nonsense value finds nothing where the site has a
   nothing, the first value answers as the walk did, and no write is sent twice.
8. **The route's own tests** are made from the sightings and kept with the body (`learn.derivation`).

**The Site oracle.** Every ask the learner makes of a site goes through one trait with two answers: `Live` (the
transport, inside the budget of `budget.rs` and the door's rest) and `Recorded` (the asks a learn made, kept beside
its walks). Offline, an ask the recording does not hold is named as a miss and never guessed. That makes the whole
learner run over the corpus in seconds, trials included, where `corpus.rs` today covers the reading of a walk only,
and it is what makes `compile` deterministic.

## 7. The caller

- Holes are filled in dependency order, backwards from the answer. Where a hole has several ways, the cheapest
  that is ready is taken; a refusal drops that hole one rung for that call (`learn.rung`).
- Every hole reports its rung. A call's rung is its highest, written to `made.jsonl` as today.
- A step's reply is kept for its lifetime, keyed by the step and the values it was sent; a step that writes is
  never skipped (`learn.lifetime`).
- Nothing in the call path decides anything. No model, no rule about which call is the answer.
- There is no repairing (`route.replace`). A route that stops passing is not edited: the caller falls to the next
  entry (`R3.19`), and the node learns the plan again as a new route. The heal paths leave the call path.
- Rung 4, a page kept open, is built once as a pool: one page a site, a cap on how many, a time to live, the
  step's request made by the page's own `fetch` or by going to the address. Today's two pieces in `mint.rs`
  (`70dbcee5`, `4a6acd50`) become that.

## 8. The work, in order

Each phase ends on a gate that is a test in this repository, named for the property. Live sites are driven one at
a time, by hand, and their answers read (`AGENTS.md`); no phase waits on a bank run.

| Phase | What is built | The gate |
|---|---|---|
| 0. Base | The branch, PR 550 merged, the base's tests run | The learn crate's tests pass on the merged base |
| 1. The body | `unbrowse-route`: the types, their file form, the evaluator, the fill order, `from_graph` | Every `Class` has an expression. A body read back is the body written. An unknown operation refuses the body. For each replay fixture, the request the new filler builds is the request `replay` builds, byte for byte |
| 2. Sightings and holes | `lab/sighting.rs`, `lab/holes.rs`, read over kept walks | Over the corpus, each kept call has a table of its holes and the axes each moved on. A value the same on two walks of different words is fixed, whatever it is tied to on one |
| 3. Expressions by example | `lab/synth.rs`, the hash search, the reply's fields | Offline, the four cases the note tested by hand come out as it found them (a hotel search of 57 holes; a picture search of 22; a list call of 7; a signed call of 28 with its hash). Every hole has a way or is listed open |
| 4. The oracle and the compiler | `lab/site.rs`, `compile.rs`, `shrink.rs`, `verify.rs` | A recording compiled twice gives the same bytes. No ask of a site is made outside the oracle (a source test, as `one_reader.rs`). A missing ask is named |
| 5. The caller | `fill.rs` over `Fetch`, rungs, lifetimes; a route file of version 2 in `unbrowse-files` | The matrix's rows answer at or below their ceilings through the new caller, the two signed rows included. A step that writes is sent once |
| 6. Functions | The function cut at the call stack, replayed with the clock and randomness answering from the recording (`learn.lab`); the pointer | Step 11's exit: a second node with no walk of the page answers a second value with no browser. A pointer to a script the page does not load is refused |
| 7. Rung 4 | The pool of open pages | A second call to a page-made step opens no new page. A page past its time is closed |
| 8. Replace | The plan kept on the route; a failed route learned again as a new one | A route that stops passing is not edited, and the next call is answered by the route learned in its place |
| 9. The switch | The new learner and caller are the default; the old paths are deleted | Corpus, matrix and each bank site driven by hand are no worse than the base on the same day, by `decide.coverage-kpi`'s count |

Phases 1 and 2 share nothing and can run side by side. Phase 3 needs both. Phase 5 needs only phase 1, because
`from_graph` feeds it. Phases 6 and 7 touch the browser and are proved live.

**What is deleted at phase 9**, and not before: the classifier in `graph::build`, the scoring in `rule_pick`,
`links.rs`, `trial.rs`'s chain surgery, the field branches of `replay.rs`, the heal paths. Their tests move with
the property they hold: a test named for a property is kept and pointed at the new code.

4. **The first ask.** The learner by example writes nothing from one walk. Default, and what the switch does
   today: the first ask is answered by one walk's reading, as now, and the route written by example takes over
   where a second walk of the page is in hand.
5. **A door that refuses the second walk.** Then there is one sighting and no route by example. Default: the
   classifier's route stands for that site until a recording keeps the learner's own asks as sightings (phase 4).
6. **Two readers of "the same call on another walk".** `lab::sighting::same_operation` tells two calls apart by a
   value that reads as a name; PR 554's `graph::align` pairs each call with its best match on the other walk, and
   has a test the name rule fails (`a_value_the_second_walk_sent_otherwise_is_never_a_constant`). Default: the lab
   takes PR 554's reader once that line is merged here, with that test as its gate, so there is one.

## 11. What would prove this wrong

- `from_graph` cannot say what a kept route does without a case per site. Then the body is missing an operation,
  and it is added as an operation or the plan is wrong about a closed list.
- Enumeration over two walks leaves most holes open on the corpus. Then the proposer carries the learner, not the
  examples, and phase 3 is a smaller gain than PR 554 already has.
- The new caller is slower than `replay` on a plain route. A warm call has no room for it.
- The line this branched from moves faster than the rebuild can follow. Then the rebuild lands in pieces behind
  the old learner (the body and the caller first) and the learner last.
