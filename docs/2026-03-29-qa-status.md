## Open Issues

### LinkedIn captureSession Failure

**Severity:** High — blocks Lane 1/2 acceptance for auth-gated sites

**Symptom:** LinkedIn feed loads authenticated content when capture steps are run manually via `kuri.evaluate`/`kuri.navigate`, but returns `chrome-error://chromewebdata/` (HTTP 400) when the same steps run inside `captureSession()`.

**What works (manual):**
On a fresh managed headless Chrome launched by Kuri:
1. `kuri.newTab("about:blank")`
2. `kuri.navigate(tab, "https://www.linkedin.com")` (origin)
3. `kuri.setCookies(tab, vaultCookies)` (38 cookies from Comet)
4. `kuri.navigate(tab, "https://www.linkedin.com/feed/")`
5. Result: `Feed | LinkedIn` with real feed content — **every time**

Even with harStart, stealth script, interceptor script, and aggressive polling re-injection — manual still works.

**What fails (captureSession):**
The exact same Chrome instance, same tab creation method, same cookie injection — but orchestrated by `captureSession()` in `src/capture/index.ts`. Page shows `chrome-error://chromewebdata/` every time.

**Ruled out:**
- CSRF token as persistent header (removed, still fails)
- harStart destabilizing CDP (tested with harStart, manual still works)
- Stealth/interceptor scripts interfering (tested with all scripts, manual still works)
- Tab creation method (both use `kuri.newTab("about:blank")`)
- Cookie injection (logs confirm 34 cookies injected in both paths)

**Not yet investigated:**
- `forceProfileContext` option in captureSession (could change Chrome launch behavior)
- `waitForContentReady()` doing something that causes a navigation/redirect
- Tab cleanup/reset logic firing prematurely due to timeout
- `trySeedStructuredDocumentSkill`/`trySeedPublicDocumentFetchSkill` running HTTP fetches before captureSession that could affect Kuri state
- Whether `captureSession` is getting a DIFFERENT tab than expected (stale tab reuse)
- Exact timing differences between manual and automated paths

**Handoff bar:** Rach's acceptance says "LinkedIn/feed-style or equivalent auth-gated repros no longer fail because Kuri crashes or tabs never become usable." Kuri doesn't crash and tabs are usable (manual test proves it). The issue is capture orchestration, not Kuri/tab reliability.

### OpenClaw Plugin Returns Unusable "Pick an Endpoint" Response to Agent

**Severity:** High — Lane 3 end-to-end is broken. Plugin connects but agent gets no usable data.

**Symptom:** When an OpenClaw agent calls the `unbrowse` tool, the CLI returns a deferred "pick an endpoint" response instead of actual data. The agent receives a message like "Found 2 endpoint(s). Pick one and call POST /v1/skills/.../execute" — which it can't act on.

**How to reproduce:**

1. Set up OpenClaw with the unbrowse plugin:
```bash
openclaw plugins install /path/to/integrations/openclaw
openclaw config set plugins.allow '["unbrowse-openclaw"]'
openclaw config set plugins.entries.unbrowse-openclaw.enabled true --strict-json
openclaw config set plugins.entries.unbrowse-openclaw.config.routingMode '"strict"' --strict-json
openclaw config unset tools.profile   # REQUIRED — "coding" profile hides plugin tools
```

2. Run an agent turn:
```bash
openclaw agent --local --agent main -m "Use unbrowse to search packages on https://www.npmjs.com/search?q=kuri"
```

3. Agent responds: "I used unbrowse but this interface doesn't expose the payload contents."

**What actually happens under the hood:**

The plugin spawns:
```bash
node dist/cli.js resolve --intent "search packages" --url "https://www.npmjs.com/search?q=kuri" --raw
```

The CLI returns a 3.1MB JSON response containing a deferred result:
```json
{
  "result": {
    "message": "Found 2 endpoint(s). Pick one and call POST /v1/skills/_l9gYPSsupMeVcK3IoKZg/execute with params.endpoint_id.",
    "skill_id": "_l9gYPSsupMeVcK3IoKZg",
    "available_operations": [
      {
        "endpoint_id": "swZzfzB0U7GOw4aksJW__",
        "action_kind": "search",
        "description_out": "Structured replay for packages",
        "requires": ["q"],
        "runnable": true
      },
      {
        "endpoint_id": "DC68FU4kQXWrhtiYBeQb0",
        "action_kind": "trending",
        "description_out": "Structured replay for get package info",
        "requires": [],
        "runnable": true
      }
    ],
    "available_endpoints": [ /* full endpoint schemas, 3MB+ */ ]
  },
  "source": "marketplace",
  "skill": { /* full skill manifest */ }
}
```

The plugin's `summarizeOutput()` function (index.ts:151) extracts `parsed.message` and returns the string "Found 2 endpoint(s). Pick one and call POST..." to the agent. The agent can't make a second API call to execute the endpoint, so it gives up.

**Two problems:**

1. **The CLI doesn't auto-execute** — it returns a deferred "choose an endpoint" response when multiple endpoints match. The autonomous eval harness (`codex-autonomous-harness.ts`) handles this by auto-selecting and executing, but the raw CLI `resolve` command doesn't.

2. **The plugin doesn't handle multi-step flows** — `summarizeOutput()` just extracts the `message` field and passes it to the agent as a string. It doesn't detect the deferred pattern and make a follow-up execute call.

3. **The response is 3.1MB** — even if the agent could read it, the full skill manifest with all endpoint schemas is way too much for an LLM context window.

**Contrast with what works:**

When the CLI auto-executes (e.g., `bun src/cli.ts resolve --intent "search repositories" --url "https://github.com/search?q=openai"` in the eval harness), it returns actual structured data:
```json
{
  "result": [
    { "full_name": "openai/openai-cookbook", "description": "...", "stargazers_count": 72400 },
    ...
  ]
}
```

This is what the agent needs — actual data, not "pick an endpoint."

**Root cause (updated):** This is NOT a plugin code bug. The `openclaw agent -m` command is **single-turn** — it sends one message, gets one LLM response, and exits. Unbrowse's tool call fires and returns a result, but the LLM never gets a second turn to process the tool result and formulate a response. This is expected behavior for single-turn mode.

The tool-result loop (LLM calls tool → gets result → reasons about it → responds) requires a **multi-turn session**. OpenClaw supports this through external channels (Telegram, Discord, Slack, etc.) or the gateway API with persistent sessions.

**How to properly test:**

1. Set up a Telegram bot via @BotFather
2. Add it to OpenClaw: `openclaw channels add --channel telegram --bot-token "TOKEN"`
3. Start the gateway: `openclaw gateway start`
4. Message the bot on Telegram: "Search for npm packages about kuri using unbrowse"

The gateway runs persistently and supports multi-turn tool-calling workflows.

**Additional setup gotchas discovered during testing:**
- `tools.profile: "coding"` hides plugin tools from the agent. Must remove it: `openclaw config unset tools.profile`
- `plugins.allow` must include `"unbrowse-openclaw"`: `openclaw config set plugins.allow '["unbrowse-openclaw"]'`
- `~/.openclaw/agents/` may be owned by root if installed with sudo. Fix: `sudo chown -R $(whoami) ~/.openclaw/agents`

## Changes Made

### Committed (PR #107)

1. **Comet browser support** — Added to BrowserSource type, macOS candidate list, SUPPORTED_INTERACTIVE_BROWSERS, DARWIN_BROWSER_BY_BUNDLE_ID, MAC_BROWSER_NAME_BY_BUNDLE_ID, CLI usage, error messages. 3 files, ~10 lines.

2. **Capture interceptor timing** — Replaced 300ms sleep with 50ms polling loop (3s deadline). Performance API replay catches missed fetch/xhr URLs and re-fetches them. Auth strategy defaults to cookie-injection. Auth headers excluded from browser headers in cookie-injection mode. 1 file, ~80 lines.

3. **QA docs** — Onboarding session notes, status report.

4. **Browser action primitive wrappers** — `snapshot()` returns `SnapshotElement[]` with refs. Added `click()`, `fill()`, `type()`, `press()`, `select()`, `scroll()`, `check()`, `uncheck()` wrappers over Kuri's `/action` endpoint.

5. **Kuri auth demo** — `evals/kuri-auth-demo.ts` replaces broken agent-browser demos. Tests scripted login on 3 sites (saucedemo, herokuapp, practicetestautomation). 3/3 pass.

## Known Gaps & Risks

### Critical
- **LinkedIn captureSession** — works manually, fails in pipeline. Unidentified divergence.
- **Lane 4 payments** — completely unbuilt. Needs product decision.

### Platform
- **Windows** — `getSupportedChromiumBrowserCandidates("win32")` returns empty array. Zero browser support.
- **Linux** — `getChromiumDecryptionKey()` calls macOS `security` command which doesn't exist on Linux. Encrypted cookies silently dropped.

### Testing
- **Untested browsers** — Arc, Dia, Brave, Edge, Vivaldi paths are in registry but never tested live. Paths follow correct Chromium conventions.
- **Auth eval demos broken** — `codex-auth-runner.ts` imports `agent-browser` (Playwright) which is removed. New Kuri-based demo (`evals/kuri-auth-demo.ts`) created as replacement.
- **Fix B limitations** — Performance API replay can't re-fetch POST requests, one-time tokens, or rate-limited endpoints. Works for 12/14 product-success sites. Proper fix requires Kuri HAR background reader (Zig architecture change).

### Deployment
- **OpenClaw npm version outdated** — Published version is v0.7.13 (depends on unbrowse ^1.1.5). In-tree v2.1.6 needs a release to publish. Workaround: install from local path.
