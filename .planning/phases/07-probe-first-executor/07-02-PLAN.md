# Plan 07-02: Proven Recipe + Decision Trace in Response Envelope

## Objective

Persist a `proven_recipe` on every admitted endpoint (the exact request that produced a known-good response) and replay it as the FIRST step of execute — before the probe ladder. When the recipe matches its `response_signal`, we're done in <500ms with no probing. When it misses, fall through to the Plan 07-01 probe ladder for re-discovery.

Also: surface `decision_trace` at the top level of every execute response (not just nested inside `trace`), so agents and the harness read it without parsing trace internals.

## must_haves

- [ ] `EndpointDescriptor` gains an optional `proven_recipe?: ProvenRecipe` field with full type definition.
- [ ] Capture pipeline (`mergeEndpoints` or `cachePublishedSkill`) stamps `proven_recipe` from the captured request/response pair when the response was a 2xx success.
- [ ] `executeEndpoint` consults `proven_recipe` BEFORE calling `probeUrl`. If the recipe replay returns a response matching `response_signal`, return immediately. If not, fall through to the probe ladder from 07-01.
- [ ] `decision_trace` is added to the execution response envelope at the top level: `{ trace, result, decision_trace, ... }`. Old nested location (under `trace.decision_trace`) is removed to avoid duplication.
- [ ] CLI (`src/cli.ts`) preserves `decision_trace` through `slimTrace`. Agents reading the JSON response see it without `--raw`.
- [ ] `recipe_replay` step is logged into `decision_trace` with: hit/miss, response status, signal-match diff if missed.
- [ ] When `proven_recipe.response_signal.status` is 200 but the actual replay returns 200 with same `content_type` and `byte_length` within 50% of recorded range, recipe is "matched" — return without probing.
- [ ] When recipe `byte_length` mismatches by ≥50% OR `content_type` differs OR status differs, recipe is "missed" — emit `recipe_replay` step with `match: false, reason` and fall through to probe.
- [ ] Backward compat: endpoints without `proven_recipe` (existing skills) skip recipe step and go straight to probe. No errors, no warnings.
- [ ] New test `tests/execution-recipe-replay.test.ts` covers: hit, miss-by-status, miss-by-content-type, miss-by-bytelength, no-recipe.
- [ ] New test `tests/execution-decision-trace.test.ts` verifies the response envelope shape: `decision_trace` is at top level and contains all steps the executor took.

```typescript
export interface ProvenRecipeResponseSignal {
  status: number;                      // exact status from the proven response (e.g. 200)
  content_type?: string;               // lowercased
  byte_length_min?: number;            // 50% of captured length, rounded down
  byte_length_max?: number;            // 200% of captured length, rounded up
  json_top_keys?: string[];            // e.g. ["data", "children"] for reddit Listing
}

export interface ProvenRecipe {
  method: string;                      // "GET" / "POST" / etc.
  url_template: string;                // includes {param} slots (entity substitution at execute time)
  headers: Record<string, string>;     // exact headers that produced the proven response
  body?: unknown;                      // exact body for POST/PUT/PATCH (undefined for GET)
  response_signal: ProvenRecipeResponseSignal;
  captured_at: string;                 // ISO-8601 timestamp of capture
}

// Add to EndpointDescriptor:
export interface EndpointDescriptor {
  // ... existing fields ...
  proven_recipe?: ProvenRecipe;
}
```

### Why

The captured response IS ground truth — we already had a working request when we captured it. Storing the recipe makes replay deterministic. The `response_signal` lets us detect drift (site changed) without re-deriving strategy.

### What to change

**File: `src/capture/index.ts`** (or wherever `mergeEndpoints` / `cachePublishedSkill` lives)

When an endpoint is admitted (added to a skill manifest from a captured request), build and attach `proven_recipe` from the actual captured request + response:

```typescript
function buildProvenRecipe(request: CapturedRequest, response: CapturedResponse): ProvenRecipe {
  const captured_at = new Date().toISOString();
  const ct = (response.headers["content-type"] || "").toLowerCase();
  const bodyLen = response.body ? Buffer.byteLength(response.body) : 0;

  // top-level JSON keys for shape comparison (cheap structural fingerprint)
  let json_top_keys: string[] | undefined;
  if (ct.includes("application/json") && response.body) {
    try {
      const parsed = JSON.parse(response.body);
      if (parsed && typeof parsed === "object" && !Array.isArray(parsed)) {
        json_top_keys = Object.keys(parsed).slice(0, 8);
      }
    } catch { /* not parseable, skip the fingerprint */ }
  }

  return {
    method: request.method,
    url_template: request.url_template ?? request.url,
    headers: pickReplayHeaders(request.headers),  // strip sec-fetch-*, ua, accept-encoding etc
    body: request.body,
    response_signal: {
      status: response.status,
      content_type: ct,
      byte_length_min: Math.floor(bodyLen * 0.5),
      byte_length_max: Math.ceil(bodyLen * 2),
      json_top_keys,
    },
    captured_at,
  };
}
```

Hook into the existing `extractEndpoints → mergeEndpoints` flow so every admitted endpoint gets a recipe (when the capture has the response body). Endpoints inferred from JS bundles (no observed response) skip the recipe.

### Why

This is the data primitive that makes replay work. Without it we re-derive strategy every call — that's where the bug class lives.

### Acceptance

- Capturing a new domain produces endpoints with `proven_recipe` set.
- `cat ~/.unbrowse/skill-cache/<skill>.json | jq '.endpoints[0].proven_recipe'` shows the recipe.

</task>

```typescript
if (endpoint.proven_recipe && shouldReplayRecipe(endpoint.proven_recipe, mergedParams)) {
```

Add helpers:

```typescript
function shouldReplayRecipe(recipe: ProvenRecipe, params: Record<string, unknown>): boolean {
  // Skip recipe replay if the URL template can't be substituted with the
  // current params (would produce a broken URL with leftover {placeholders}).
  // Re-discovery via probe ladder is safer.
  return !/\{[a-z0-9_]+\}/i.test(interpolate(recipe.url_template, params));
}

async function replayRecipe(
  recipe: ProvenRecipe,
  url: string,
  cookies: Array<{name: string; value: string}>,
  authHeaders: Record<string, string>,
  params: Record<string, unknown>,
): Promise<{status: number; data: unknown; trace_id: string}> {
  const headers = { ...recipe.headers, ...authHeaders };
  if (cookies.length > 0) {
    headers["cookie"] = cookies.map((c) => `${c.name}=${c.value}`).join("; ");
  }
  const body = recipe.body ? interpolateObj(recipe.body as Record<string, unknown>, params) : undefined;
  try {
    const res = await fetch(url, {
      method: recipe.method,
      headers,
      body: body ? JSON.stringify(body) : undefined,
      redirect: "follow",
    });
    const text = await res.text();
    let data: unknown = text;
    try { data = JSON.parse(text); } catch { /* keep text */ }
    return { status: res.status, data, trace_id: nanoid() };
  } catch (err) {
    return { status: 0, data: { error: (err as Error).message }, trace_id: nanoid() };
  }
}

interface MatchVerdict { match: boolean; reason?: string }
function matchResponseSignal(
  result: {status: number; data: unknown},
  signal: ProvenRecipeResponseSignal,
): MatchVerdict {
  if (result.status !== signal.status) {
    return { match: false, reason: `status_changed: ${signal.status} → ${result.status}` };
  }
  // Byte length within range
  const bodyLen = typeof result.data === "string" ? result.data.length : JSON.stringify(result.data).length;
  if (signal.byte_length_min !== undefined && bodyLen < signal.byte_length_min) {
    return { match: false, reason: `body_shrunk: ${bodyLen}B < min ${signal.byte_length_min}B` };
  }
  if (signal.byte_length_max !== undefined && bodyLen > signal.byte_length_max) {
    return { match: false, reason: `body_grew: ${bodyLen}B > max ${signal.byte_length_max}B` };
  }
  // JSON top keys (cheap structural fingerprint)
  if (signal.json_top_keys && result.data && typeof result.data === "object" && !Array.isArray(result.data)) {
    const actual = new Set(Object.keys(result.data as object));
    const missing = signal.json_top_keys.filter((k) => !actual.has(k));
    if (missing.length > 0) {
      return { match: false, reason: `missing_top_keys: ${missing.slice(0, 3).join(",")}` };
    }
  }
  return { match: true };
}
```

### Why

Recipe replay is the fast path for everything we've already proven works. For the reddit case: replay recipe (200ms) → status 200 + content-type matches + body within range → done. No probe needed. For drift cases (site changed, anti-bot rotated): match fails → probe ladder picks up.

### Acceptance

- Endpoint with valid recipe + matching response → recipe_replay step succeeds, no probe step.
- Endpoint with recipe but server returned 403 → recipe miss, probe ladder runs, `decision_trace` shows both.
- Endpoint with no recipe → no recipe_replay step, probe ladder runs as before.

<task id="4" title="Surface decision_trace at response top level">

### What to change

**File: `src/execution/index.ts`** — `finalizeExecuteResult` (new helper):

```typescript
function finalizeExecuteResult(
  trace: ExecutionTrace,
  result: {status: number; data: unknown; trace_id: string},
  decisionTrace: Array<Record<string, unknown>>,
): ExecutionResult {
  // Set status_code, success, error on trace as today.
  trace.status_code = result.status;
  trace.success = result.status >= 200 && result.status < 300;
  if (!trace.success && !trace.error) {
    trace.error = `HTTP ${result.status}`;
  }

  return {
    trace,
    result: result.data,
    decision_trace: decisionTrace,
  };
}
```
