# Plan 03-02: Live Capture Fallback and Conditional UI Actions

## Objective

Wire the live capture path into `page.goto()` for uncached sites (the agent is unaware capture happened), and implement BROWSER-02 UI actions with graceful degradation when Rach's kuri hook is unavailable.

## must_haves

- [ ] `page.goto()` on uncached site transparently runs `captureSession` and returns page result
- [ ] Background indexing is queued after live capture so next visit resolves from cache
- [ ] `page.click(selector)` works via kuri ref-based actions when available, evaluate fallback otherwise
- [ ] `page.fill(selector, value)` works via kuri ref-based actions when available, evaluate fallback otherwise
- [ ] `page.waitForSelector(selector)` delegates to kuri or polls via evaluate
- [ ] Feature detection: `kuri.snapshot(tabId)` success gates ref-based vs evaluate-based path
- [ ] All actions: passive capture continues underneath

## Notes

- BROWSER-02 (ref-based actions via kuri.domQuery/click/fill) is blocked on Rach. The evaluate fallback ships now.
- Feature detection happens once per Page instance — cached for the page lifetime.

## Tasks

<task id="1" title="Wire live capture fallback into page.goto">

### What to change

**File:** `src/browser/index.ts`

In `page.goto()`, when `resolveAndExecute` returns no skill match or fails:
1. Call `captureSession(url, undefined, undefined, intent)` transparently
2. Store captured HTML in the Page instance
3. Queue `queueBackgroundIndex` so next visit resolves from cache
4. Return `UnbrowseResponse` with status 200 + page HTML
5. Same return shape as skill-resolved path — agent can't distinguish

</task>

<task id="2" title="Implement conditional UI actions with graceful degradation">

### What to change

**File:** `src/browser/index.ts`

- `page.click(selector)`:
  - Try `kuri.domQuery(tabId, selector)` → ref → `kuri.click(tabId, ref)`
  - On failure: `kuri.evaluate(tabId, "document.querySelector(sel).click()")`
- `page.fill(selector, value)`:
  - Try `kuri.domQuery` → ref → `kuri.fill(tabId, ref, value)`
  - On failure: evaluate-based fill
- `page.waitForSelector(selector, opts)`:
  - Delegate to `kuri.waitForSelector(tabId, selector, opts.timeout)` if available
  - Fallback: poll via evaluate every 200ms
- Feature detection: call `kuri.snapshot(tabId)` once on first action; cache result on Page

</task>
