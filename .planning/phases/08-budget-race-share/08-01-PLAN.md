# Plan 08-01: Per-call Latency Budget + Parallel Race

## Objective

Replace the serial resolve pipeline with a parallel race of three lookups (recipe replay || marketplace lookup || HEAD probe) bounded by a per-call wall-clock budget. First valid response wins; deadline returns `no_match` with `tried: [...]` and an actionable `next_step`. Marketplace lookups get a 5-min in-process TTL.

## must_haves

- [ ] CLI accepts `--budget <ms>` on `unbrowse resolve` (and the equivalent MCP arg). Default 8000.
- [ ] `resolveAndExecute` (or a new `resolveWithRace`) fires three lookups in parallel using `Promise.race`-with-deadline:
  - local recipe replay (uses Phase 7 `proven_recipe` infrastructure)
  - marketplace lookup (with new 5-min in-process TTL cache)
  - HEAD probe of the URL (uses Phase 7 `probeUrl`)
- [ ] First lookup that returns a "valid" result wins. Validity rules:
  - recipe replay: `match: true` against `response_signal`
  - marketplace lookup: any non-empty endpoint shortlist
  - probe: status 2xx-3xx with content-type that suggests data
- [ ] Losing in-flight requests are aborted via `AbortController` when a winner is announced.
- [ ] Deadline timeout returns:
  ```json
  { "status": "no_match", "tried": ["recipe", "marketplace", "probe"], "ms": 503,
    "next_step": { "command": "unbrowse capture --url ... --intent ...", "est_ms": 8000, "creates_skill": true } }
  ```
- [ ] `decision_trace` (Phase 7) records each racer's start, end, status, and which one won.
- [ ] Marketplace TTL: a 5-minute in-process LRU cache keyed by `(skill_id, domain)`. Invalidated on `publishSkill` for the published domain.
- [ ] Resolve NEVER opens a Kuri tab. The browser-capture path is moved to the standalone `unbrowse capture` verb in Plan 08-02.
- [ ] Existing `unbrowse resolve` callers without `--budget` get the 8000ms default and observe identical behavior, EXCEPT no longer auto-trigger live capture (they get `next_step` instead).
- [ ] All `tests/resolve-*.test.ts` continue to pass after fallback path is removed.

## Tasks

<task id="1" title="Build the race primitive">

### What to change

**File: `src/orchestrator/resolve-race.ts`** (new)

```typescript
export interface Racer<T> {
  name: string;
  start: () => Promise<T>;
  isValid: (result: T) => boolean;
  abort?: () => void;
}

export interface RaceResult<T> {
  winner: { name: string; result: T; ms: number } | null;
  tried: Array<{ name: string; status: "won" | "lost" | "deadline"; ms: number }>;
}

export async function raceWithDeadline<T>(
  racers: Racer<T>[],
  budgetMs: number,
): Promise<RaceResult<T>>;
```

Uses `Promise.race` against a deadline timer. On first valid result, calls `abort()` on every other racer and returns. On deadline, calls every `abort()` and returns `{winner: null, tried: [...]}`.

### Acceptance

- 3 racers all return — fastest valid wins
- 1 racer is valid, 2 throw — valid one wins
- All 3 throw — `winner: null`
- All 3 slow > deadline — `winner: null`, every `tried` entry has `status: "deadline"`
- Aborts fire on losers (test via spy)

</task>

<task id="2" title="5-min marketplace TTL cache">

### What to change

**File: `src/marketplace/index.ts`**

Add an in-process LRU cache (use the existing `lru-cache` dep if present, else a simple `Map` with a 100-entry cap):

```typescript
const marketplaceCache = new Map<string, { skill: SkillManifest; expires: number }>();
const TTL_MS = 5 * 60 * 1000;

export async function getSkillCached(skill_id: string, scope: ClientScope): Promise<SkillManifest | null> {
  const key = `${scope}:${skill_id}`;
  const cached = marketplaceCache.get(key);
  if (cached && cached.expires > Date.now()) return cached.skill;
  const fresh = await getSkill(skill_id, scope);
  if (fresh) marketplaceCache.set(key, { skill: fresh, expires: Date.now() + TTL_MS });
  return fresh;
}

export function invalidateMarketplaceCache(skillIdOrDomain: string): void {
  for (const key of marketplaceCache.keys()) {
    if (key.includes(skillIdOrDomain)) marketplaceCache.delete(key);
  }
}
```

`publishSkill` calls `invalidateMarketplaceCache(domain)` after a successful publish so other agents see the new skill within the publish window.

### Acceptance

- Same skill_id resolved twice within 5 min: 1 backend hit, 1 cache hit
- After 5 min: backend hit
- After explicit publish: cache busted for that domain

</task>

<task id="3" title="Wire race into resolveAndExecute">

### What to change

**File: `src/orchestrator/index.ts`** — `resolveAndExecute` (around the route_cache → marketplace → first_pass logic, ~line 2100-2400):

Build the three racers from existing primitives:

```typescript
const racers: Racer<ResolveCandidate>[] = [
  {
    name: "recipe",
    start: () => attemptRecipeReplay(contextUrl, intent, params, signal),
    isValid: (r) => r?.match === true,
  },
  {
    name: "marketplace",
    start: () => searchMarketplaceCached(intent, contextUrl, scope, signal),
    isValid: (r) => Array.isArray(r?.endpoints) && r.endpoints.length > 0,
  },
  {
    name: "probe",
    start: () => probeUrl(contextUrl, { cookies, headers: authHeaders, timeout_ms: budget }),
    isValid: (r) => r.status >= 200 && r.status < 400 && !!r.content_type,
  },
];

const race = await raceWithDeadline(racers, budget);

if (race.winner) {
  return formatWinner(race);
}

return formatNoMatch(race, contextUrl, intent);
```

Delete the existing serial fallback chain (route_cache → marketplace → first_pass_browser → handoff). Keep route_cache integrated INTO the recipe racer (it's already replay).

`formatNoMatch` builds the `next_step` payload with the `unbrowse capture` command line and est_ms.

### Acceptance

- Resolve with budget 500ms returns within 500ms ± 50ms
- All `tests/resolve-*.test.ts` adapted/pass — none rely on the auto-browser-fallback (those tests get rewritten in Task 5)

</task>
