# Plan 02-02: Wire Background Indexer + Cache-First Resolution

## Objective

Modify `executeBrowserCapture` to write skills to local cache immediately after extraction and defer graph building + marketplace publish to the background indexer. This ensures: (1) the agent gets the capture result ~1.5s faster, (2) the local skill cache is populated before auto-exec, so second resolve calls find the cached skill without launching kuri or hitting the marketplace.

## must_haves

- [ ] `executeBrowserCapture` writes skill to local snapshot cache BEFORE marketplace publish
- [ ] `executeBrowserCapture` writes to `domainSkillCache` BEFORE marketplace publish
- [ ] Graph building + `validateManifest` + `publishSkill` are deferred to background indexer
- [ ] Synchronous `validateManifest` + `publishSkill` calls removed from `executeBrowserCapture` response path
- [ ] Second `resolve` call for a previously-captured domain returns from local cache without launching kuri
- [ ] Cache-first falls through to marketplace on local miss, then to live capture as last resort
- [ ] Cached skills execute correctly and return structured data (functional equivalence with active capture)

## Notes

- **Intentional behavioral change**: The `learned_skill` returned from `executeBrowserCapture` will NOT have `operation_graph` on first return. The background indexer builds it. `ensureSkillOperationGraph` (line 726 of `src/graph/index.ts`) handles this gracefully by building the graph on-the-fly when missing. This is safe because `operation_graph` is only used for DAG planning in deferral responses, not for execution.
- **Marketplace fallthrough is inherited**: The resolve cascade in `resolveAndExecute` already checks local cache → marketplace → live capture in that order (lines 2645-3026). No resolve-side changes are needed. SC-3 is satisfied by the existing cascade code.

**Replace lines ~1356-1390** (the synchronous publish path) with:

```typescript
  // Build local skill draft
  const localDraft: SkillManifest = {
    skill_id: existingSkill?.skill_id ?? nanoid(),
    version: "1.0.0",
    schema_version: "1",
    lifecycle: "active" as const,
    execution_type: "http" as const,
    created_at: existingSkill?.created_at ?? new Date().toISOString(),
    updated_at: new Date().toISOString(),
    name: domain,
    intent_signature: intent,
    domain,
    description: `API skill for ${domain}`,
    owner_type: "agent" as const,
    endpoints: localEndpoints,
    intents: Array.from(new Set([...(existingSkill?.intents ?? []), intent])),
    ...(auth_profile_ref ? { auth_profile_ref } : {}),
  };

  // Generate local descriptions immediately so BM25 ranking works on first cache hit
  for (const ep of localDraft.endpoints) {
    if (!ep.description) {
      ep.description = generateLocalDescription(ep);
    }
  }

  // PHASE 2: Write local cache IMMEDIATELY (~1ms) — populates cache before auto-exec
  const bgCacheKey = buildResolveCacheKey(domain, intent, url);
  const bgScopedKey = scopedCacheKey(options?.client_scope ?? "global", bgCacheKey);
  writeSkillSnapshot(bgScopedKey, localDraft);
  const bgDomainKey = getDomainReuseKey(url ?? domain);
  if (bgDomainKey) {
    domainSkillCache.set(bgDomainKey, {
      skillId: localDraft.skill_id,
      localSkillPath: snapshotPathForCacheKey(bgScopedKey),
      ts: Date.now(),
    });
    persistDomainCache();
  }

  // PHASE 2: Queue heavy work for background (graph + validate + publish)
  queueBackgroundIndex({
    skill: { ...localDraft },
    domain,
    intent,
    contextUrl: url,
    clientScope: options?.client_scope,
    cacheKey: bgCacheKey,
  });

  // Return the local draft as learned_skill — no blocking on marketplace publish
  let learned: SkillManifest = localDraft;
  try { cachePublishedSkill(localDraft, options?.client_scope); } catch { /* best-effort */ }
```

### Steps


   ```bash

   ```

   ```bash

   grep -q "background-index.*queued" /tmp/phase2-first-resolve.log && echo "PASS: indexer queued" || echo "FAIL: indexer not queued"
   ```

5. Second resolve (should hit local cache — different intent, same domain):
   ```bash
   bun src/cli.ts resolve --intent "find open issues" --url "https://github.com/search" --pretty 2>&1 | tee /tmp/phase2-second-resolve.log
   ```

6. Verify second resolve used cache:
   ```bash
   # Must show cache hit
   grep -qE "(domain-cache|local-snapshot).*hit" /tmp/phase2-second-resolve.log && echo "PASS: cache hit" || echo "FAIL: no cache hit"
   # Must NOT show kuri browser launch
   grep -qv "captureSession" /tmp/phase2-second-resolve.log && echo "PASS: no kuri launch" || echo "FAIL: kuri was launched"
   ```

7. **Execute a cached skill endpoint (SC-4: functional equivalence)**:
   Extract the skill_id from the second resolve response and execute an endpoint:
   ```bash
   # Parse skill_id from resolve response
   SKILL_ID=$(grep -o '"skill_id":"[^"]*"' /tmp/phase2-second-resolve.log | head -1 | cut -d'"' -f4)

   bun src/cli.ts execute --skill-id "$SKILL_ID" --pretty 2>&1 | tee /tmp/phase2-execute.log
   # Verify structured data returned
   grep -qE '"(data|results|items|entries)"\s*:' /tmp/phase2-execute.log && echo "PASS: structured data" || echo "WARN: check response manually"
   ```

8. Wait for background indexer to complete:
   ```bash
   sleep 5
   grep -q "background-index.*completed" /tmp/phase2-first-resolve.log && echo "PASS: indexer completed" || echo "INFO: indexer may still be running"
   ```
