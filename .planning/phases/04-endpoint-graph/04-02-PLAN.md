# Plan 04-02: Prefetch Integration and Graph-Aware Resolve

## Objective

Rewrite `src/capture/prefetch.ts` with proper graph edge traversal (following `parent_child` edges), wire it into the orchestrator so agents get related endpoint data in one round-trip, and replace the flat `available_endpoints` with graph-reachability-filtered endpoints.

## must_haves

- [ ] `src/capture/prefetch.ts` rewritten with `getPrefetchTargets` and `executePrefetch` using graph traversal
- [ ] Prefetch follows only `parent_child` edges from the resolved operation
- [ ] Only GET endpoints are prefetched (safe, idempotent)
- [ ] Max 3 prefetched operations, 2s timeout each — failures non-fatal
- [ ] `tryAutoExecute` wires prefetch after successful execution, includes `prefetched` in result
- [ ] `buildDeferral` filters `available_endpoints` by `computeReachableEndpoints` given known bindings
- [ ] Backward compatible — no prefetch targets = identical response to pre-Phase-4

## Tasks

<task id="1" title="Rewrite prefetch module with graph traversal">

### What to change

**File: `src/capture/prefetch.ts`** (FULL REWRITE)

Replace entire file with graph-based implementation:
- `getPrefetchTargets(graph, resolvedOperationId, knownBindings)` — traverse `parent_child` edges from resolved op, return targets whose bindings are satisfiable
- `executePrefetch(skill, targets, params)` — execute targets in parallel with 2s timeout each, catch failures
- Constants: `PREFETCH_MAX = 3`, `PREFETCH_TIMEOUT_MS = 2000`
- Types: `PrefetchTarget`, `PrefetchResult`
- Only prefetch GET endpoints; check `isRunnable` with effective bindings (resolved op's provides + known)

   - Log: `[prefetch] N target(s) for endpoint, M/N succeeded`
