## What works

### Auth DAG — browse once, call APIs forever
- Browse any authenticated site → HAR captures → endpoints enriched with `auth_tokens` bindings
- Execute → token resolver fires → opens tab → resolves fresh bearer from JS bundles + CSRF from cookies
- DAG overrides vault — fresh tokens every time
- Performance API fallback scans ALL script resources when stored URLs miss
- Tested end-to-end: X Ads API returns live campaign data (account, spend, impressions)

### X Ads campaign LIVE
- Campaign `oia9s`: SGD 40/day, WEBSITE_CLICKS, ACTIVE + SERVING
- 9 keywords (playwright alternative, browser automation, mcp browser, etc.)
- 7 countries (US, UK, CA, DE, IN, AU, SG)
- Created entirely via API — no browser UI needed
- All API learnings documented in memory (`reference_x_ads_api_learnings.md`)

### Verified/unverified endpoints
- First publish → unverified
- Different agent executes successfully → verified (+15 rank boost, +10% reliability)
- Backend wired: scoring.ts compares executor vs indexer agent IDs

### Package overhaul
- Server bun-built to `dist/server.js` — no tsx runtime interpretation
- `runtime-src/` removed from npm (was leaking source code)
- Cold start fixed: retry waitForLoad 5x + health check fallback
- CI: `clean: true` checkout, Zig 0.15.2, pre-built Kuri binary

## Known issues

1. **Kuri SIGSEGV on adding-extensions branch** — intermittent segfault on heavy SPAs. Doesn't affect functionality (retry recovers).
2. **Extension relay not functional** — background→relay→content postMessage chain produces 0 entries. Cookie fallback covers auth inference.
3. **Frontend deploy** — R2 auth fails for experiments env. Prod frontend was overwritten (fixed with --env experiments).
4. **Cards API** — X Ads cards endpoint returns 403 on cookie auth. Workaround: URL in tweet text auto-generates card from og:tags.
