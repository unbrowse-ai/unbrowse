## The three Day-3 unknowns, resolved

### 1) `R2_BUCKET` declared required but unbound — RESOLVED (safe)

- Only call-site: `backend/src/services/demo-pipeline.ts:112`.
- Sole importer: `backend/src/routes/demos.ts`.
- `routes/demos.ts` is **not imported** anywhere in `src/` — confirmed by
  `grep -rn "routes/demos\|from.*demos" backend/src/` returning nothing
  outside the file itself.
- Wrangler dry-run binding list contains no R2 binding and does not
  error — the field is dead code at runtime on every existing environment
  (prod included). The type field should be made optional in a follow-up,
  but it does not block deploy.

### 2) CASCADE prefix mismatch — RESOLVED (degraded, intentional-or-bug)

- Source reads bare `env.CASCADE_PLATFORM_WALLET` etc.
  (`backend/src/services/cascade.ts:64-98`, `services/sponsor-pay.ts:33-35`).
- Staging secret store has them under `UNBROWSE_CASCADE_*` prefix
  (4 secrets, confirmed by `wrangler secret list`).
- **There is no mapping layer.** `grep -rn UNBROWSE_CASCADE backend/`
  returns zero hits.
- Runtime impact: `isCascadeConfigured()` in `services/cascade.ts:63-68`
  returns `false`, so all cascade payout branches short-circuit. No crash;
  cascade rewards are silently disabled on staging.
- Action item (post-deploy, not a blocker): either rename the staging
  secrets to bare `CASCADE_*` or add a mapping at startup. Prod likely
  has the same shape — verify before next prod release.

### 3) `FAL_KEY` and `TURBOBOX_URL` missing from staging — RESOLVED (safe)

- Both only used in `services/demo-pipeline.ts`, reached only via the
  unmounted `routes/demos.ts`. Same dead-code conclusion as R2_BUCKET.
- Type fields should also be made optional in a follow-up; not blocking.
